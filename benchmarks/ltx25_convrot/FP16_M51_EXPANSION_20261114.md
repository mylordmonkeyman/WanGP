## Low-overhead implementation under test

`LTX25_FP16_GEMM_BACKEND=direct` temporarily wraps only the Python `torch.ops.quanto.qbytes_mm` entry during a transformer forward. The native operator overload is saved and restored in `finally`, including on failure. Nonselected operations call the exact native Quanto op, and selected operations run temporary FP16 matmul. This avoids the prior `TorchDispatchMode` Python callback on >1 million unrelated ATen operations per video.

**Research-only caveat:** this is a process-wide mutable Python operator namespace and is NOT thread-safe if simultaneous model inference occurs in the same Python process. Do not enable in production by default. Tested only in isolated single-model runner processes.

Size thresholds are independently overridable (`LTX25_FP16_GEMM_MIN_M`, `LTX25_FP16_GEMM_MIN_DIM`). An exact stage:M:N:K allowlist (`LTX25_FP16_GEMM_ALLOW_SHAPES`) prevents untested workloads from automatically receiving FP16. The existing first-per-shape finite guard and numerical audit remain available; native Quanto and sham BF16 remain the controls.

A real 49-frame, all-shape expanded T2V ABBA and quality sweep has been dispatched. **Do not infer wall-clock wins or accept visual fidelity from isolated microbenchmarks.** Compare native A/Z, BF16-sham A/B/B/A, real FP16 conversions, decoded frame PSNR/audio and numerical-error samples first. Stage 1 previously had large video deviation even at small numerical RMS error, so Stage 2 is a safer initial candidate.

## Production gates

1. Run on an idle V100 with the same image/prompt/seed, 49 frames first; then repeat at the intended longer frame count.
2. Require nonzero and expected real Quanto FP16 conversions, plus no nonfinite audit outputs.
3. Require BF16 sham decoded video/audio identical to native and restored operator namespace after the transformer.
4. Require reliable **whole-process**, load-inclusive time savings vs both native and dispatch-matched sham, not CUDA microbenchmark savings alone.
5. Review perceptual video/audio changes; reject any FP16 setting that causes unacceptable motion, face, texture or audio artifacts.
6. Do not create persistent duplicate FP16 weights in VRAM or silently modify the production Candidate E defaults.
